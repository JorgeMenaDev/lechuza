# Lechuza

On-device meeting recorder and dictation for macOS. Bun workspaces (`packages/contracts`, `apps/desktop` Electron main, `apps/web` React renderer) plus `engine/`, the Swift helper `lechuza-engine`. Read `README.md` for the architecture.

- Checks: `bun run typecheck`, `bun test`, and `swift test --package-path engine`. The engine's speech test downloads Parakeet v3 (~470 MB) on its first run.
- Every app change ships: a merge to `main` publishes a beta (a GitHub pre-release with the DMG), and a stable release promotes a beta someone tested. To ship, promote, or recover a failed release, follow `.agents/skills/release/SKILL.md`. The release workflow runs typecheck and `bun test` but not the engine's tests (its speech test downloads the model), so run `swift test` before merging engine changes.
- Main owns all state. `apps/desktop/src/meetings.ts` owns the meeting part (`MeetingsState`) and `dictation.ts` the dictation part; `main.ts` adds `settings` (saved in `settings.json` in the app's data folder) and `info` to make the `AppState` it broadcasts. The renderer sends intents through `window.lechuza` and renders that state. Add a capability in this order: contracts type + channel, preload, main handler, renderer.
- The app and engine speak JSON lines on stdio. A message lives in three places that change together: `packages/contracts/src/engine.ts`, `engine/Sources/LechuzaEngine/Protocol.swift`, and one example in `packages/contracts/fixtures/engine-protocol.json`, which both sides' tests decode.
- Dictation is separate from meetings: the engine's `Dictation/` has its own microphone capture and its own Parakeet instance, so a dictation never touches a recording. The Flow bar is a second window on the same bundle (`#/flow-bar`, `surfaces/FlowBar.tsx`).
- macOS grants Documents, Microphone, System Audio Recording and Accessibility (the dictation key's event tap and the ⌘V that pastes) to the app that launched the engine. Packaged, that is Lechuza, because main spawns `Contents/Resources/lechuza-engine` as its child. Under `bun run dev` it is the terminal's app (T3 Code), so the prompts never name Lechuza there; prove permission behaviour on a `bun run dist` build launched with `open`.
- Signed builds use the hardened runtime: `apps/desktop/build/entitlements.mac.plist` must keep `com.apple.security.device.audio-input`, and `build.mac.extendInfo` in `apps/desktop/package.json` its usage strings, or macOS blocks capture with no prompt.
- This Mac has a Developer ID identity, which electron-builder picks first. Local `bun run dist` signs with Apple Development: `CSC_NAME="Apple Development: <name>" bun run dist`.
- Every style is in `apps/web/src/index.css`, under semantic class names. Components carry class names only, except live values that change while you watch (a level meter's width, the playback position, the Flow bar's `--level`), which they set inline as `index.css` allows. Its colour variables come in a light and a dark set. The Theme setting sets `nativeTheme.themeSource`, which drives `prefers-color-scheme`, so CSS needs nothing else for dark mode.
- Fonts (Figtree, EB Garamond) come from Fontsource and icons from Lucide. Their licences are in `NOTICE`; a new bundled font, icon set or image adds its licence there.
- The app icon, `apps/desktop/build/icon.icns`, is generated from `assets/icon.svg` by `bun apps/desktop/scripts/app-icon.ts`. The menu bar owl is `assets/tray.svg`, rendered by `apps/desktop/scripts/tray-icon.ts`.
- Electron won't start if `ELECTRON_RUN_AS_NODE=1` is set (T3 Code terminals set it). Prefix commands with `env -u ELECTRON_RUN_AS_NODE`, `open /Applications/Lechuza.app` included: `open` passes the shell's environment on.
- Bun's bundler bakes `__dirname` in at build time. Resolve app files from `app.getAppPath()`.
- `LECHUZA_MEETINGS_DIR` points the app at another meetings folder, and Electron's `--user-data-dir=<folder>` gives it its own settings and dictation history. Use both for tests, demos and screenshots, so real meetings and dictations stay out of them.
- To test dictation without a person, set the key to right Option and post its flagsChanged events with `CGEvent` (key code 61, flags `maskAlternate | 0x40` down). Never synthesise `fn`: other dictation apps on the Mac listen to it too. Wait about 50 ms before the posting process exits, or macOS can drop the event. Speak with `say` and read the text back from TextEdit with AppleScript.
- After each new engine build, the first Parakeet load compiles the model for the Neural Engine (about 20 s). Wait for `AsrManager loaded successfully` on the engine's stderr before timing a dictation.
